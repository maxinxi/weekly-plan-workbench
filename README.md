# 周计划与日计划工作台

## 日计划：只需下载一份 HTML

[下载「日计划工作台.html」](https://raw.githubusercontent.com/maxinxi/weekly-plan-workbench/main/%E6%97%A5%E8%AE%A1%E5%88%92%E5%B7%A5%E4%BD%9C%E5%8F%B0.html) · [下载「日计划处理.py」](https://raw.githubusercontent.com/maxinxi/weekly-plan-workbench/main/%E6%97%A5%E8%AE%A1%E5%88%92%E5%A4%84%E7%90%86.py)

**日计划 HTML 已内嵌网页和原版 Python，调用本机已安装的 Python 与 Microsoft Excel；使用时无需联网。** 它与下面完全在浏览器里运行的周计划版本相互独立。

1. HTML 下载到任意位置，用 Edge / Chrome 打开。点击 **下载 Python 启动文件**，双击下载的 `启动日计划工作台.py`，浏览器会自动打开本机工作台。已取消带内嵌命令的 CMD，避免 Windows 安全中心将下载脚本拦截。若 `.py` 被打开成文字，右键选择 **打开方式 → Python**；以后可重复使用这个启动文件。
2. 工作台打开后，像周计划一样把当天现场作业计划和风险管控两份 XLSX **一起拖入虚线框**，再点“初步整理并核对”。拖入方式可下载完整 `（处理后）.zip`。若要求自动写到源表当前目录，点击虚线框选择文件，或点 **从本机窗口选择两份源表**；每份原件旁只备份一次到 `源文件备份/`，已有备份不覆盖，正式输出直接进入同目录的 `（处理后）`，无需再选择输出目录。
3. 程序先排除示例、全空白、非作业行和合并续行，再核对两表有效作业数量。核对不依赖行顺序：先按规范化工作内容对应；文字略有差异时，仅用唯一的“负责人姓名/电话＋开始时间＋结束时间”复合锚点对应并告警，不做模糊猜测。
4. 只有 **同进同出人员原本为空，且同进同出人员层级明确为“领导人员”** 的作业显示选择框并参与完成检查。管理人员、业务骨干等其他层级不显示选择，也不阻止生成；原本已有人员的单元格按源表保留。需要选择的行读取当前文件隐藏 Sheet4 的关联名单，缺少本行规则时从“例”行继承；复杂公式可点击 **重新读取下拉公式（Excel）**。
5. 全天同一人只选左侧；上午、下午不同人分别选择，点击 **将选择写入同一格**。人员、电话和“上午/下午”保留在同一格。填写空白人员单元格时保留相邻人员层级等全部关键字段；交付前再次检查源表及到岗到位版的层级内容。网页修改只写到源表工作副本，**不将人员选择同步到风险管控**。
6. 点击 **查看模式 A**，由原 Python 生成缩写版及完整版，可直接复制。日期非法、缺日期、起止异常、标题/文件名冲突、两表同一作业时间不同、不能唯一配对等均在网页告警。告警同时标明“整理后第几项”和“原表第几行”。不确定差异展开两边原值及匹配原因，由用户选择采用现场表、采用风险表或保留告警，程序不预设正确一方。不会凭数量差自动增删作业。
7. 所有需要领导的空白行完成选人后，自动询问是否生成到岗到位。保留 **运检专业、营销专业、公司领导** 三项首页侧栏输入。确认后调用原版列转换、字体、列宽、续行、分页、合并和边框流程；最终已保存的现场计划用于生成模式 A/B。
8. 最终输出 **源表、到岗到位、风险管控三份 Excel + 到岗到位、风险管控两份 PDF**，以及文字汇总和修改报告。两个 PDF 直接由 **Excel ExportAsFixedFormat** 生成。生成后直接显示文件位置，**不再自动弹出打印预览**。需要打印时，在结果区点击 **选择文件 · 调整 / 打印**，选择到岗到位或风险管控 PDF；默认 A3 横向。
9. 预览中的 **调整框线 / 行高后重新生成** 可主动选择线宽、颜色及额外行高。默认仍为原版细线和原版余量，不自行修改字体、列宽或分页算法。**原版排版结束后，删除只有序号、其余为空的行，再核对序号、收紧打印区域并导出 PDF。** 到岗到位版最终沿用原版细线补齐重复表头自身的下框线，避免第二页漏线；原 L/M 侧栏跨页留空规则保持不变。真正承载工作内容的合并续行不删除；还有其他数据但缺工作内容的行单独告警。

Python 版也已内嵌网页和原版代码，双击 `日计划处理.py` 即可启动同一工作台。需要 Windows、Microsoft Excel（含支持 A3 的 Microsoft Print to PDF 驱动）、Python 的 `openpyxl`、`pandas`、`pywin32`。若缺少依赖，启动错误会列出缺项；安装命令为 `python -m pip install -r requirements-daily.txt`。**已装好这些程序的电脑，只下载 HTML 即可，不必单独下载 Python 文件。**

`daily_plan_legacy.py` 是用户提供的 5.6 版原文件，保留作对照，不修改其业务算法。**不要直接运行该参考文件的 main**，它保留原有扫描当前目录和结束 Excel 进程的行为；交付入口只调用其单项处理函数，且仅传入临时 work 副本，不结束用户已有 Excel。工作副本成功或失败均清理；输出写入失败会回滚本次替换。为获得原版 A3 打印度量，生成期间暂用 Microsoft Print to PDF 驱动，结束后恢复原默认打印机。

可选的 `模式B语义检索库.py` 及其审核语料如果需要继续使用，放在临时启动文件同目录，沿用原版加载规则；不提供该可选库时，沿用原代码已有的内置规则回退，不杜撰审核案例。私人名单、真实工作簿、PDF 和审核数据库不纳入仓库。

## 使用

1. 拖入原始「表1.xlsx」。网页读取文件，在本机浏览器处理。
2. 查看处理日志；能确定的换行、时间分隔符自动修复。日期、时间等不能确定的问题保留原值并报告。
3. 点击 **保存源表及明细**，下载「（处理后）.zip」。解压后源表、明细和报告统一位于「（处理后）」文件夹。也可单独下载源表或明细的ZIP。
4. 源表保留原始文件名；明细仅命名为 **（第36周）（周计划明细）.xlsx** 这种格式。**周计划明细不带管控措施。** 风险汇总和项目汇总仍可单独下载。
5. 点击 **源文件备份 ZIP** 保存原件备份；需要核对时下载源表处理报告。

无需选择输出目录。Python版直接在源文件所在目录创建「（处理后）」；单文件HTML拿不到导入文件的原始目录写入权限，因此下载ZIP到浏览器默认下载位置，解压即得到同样文件夹结构。HTML不提供目录选择，也不会声称已自动写回原文件夹。找不到周次时，明细使用「周计划明细.xlsx」，不猜测周次。

```text
源文件所在目录/
  表1：每周重点作业计划（第36周）.xlsx
  （处理后）/
    表1：每周重点作业计划（第36周）.xlsx
    （第36周）（周计划明细）.xlsx
    表1：每周重点作业计划（第36周）.报告.json
```

默认采用第37周成品的排版方向：保留已有宽列、原字号和加粗；48磅不会改小。原打印缩放能容纳A3宽度时保留（包括10%），否则设为一页宽、高度不限。保留已有有效打印列范围，每页重复标题和表头，尽量在完整作业之间分页；单个作业过长时在管控措施块之间分页。单块超过一页时明确报告。

「管控措施行高增量」默认 **+1磅**，可改为0或2。取消「保留成品宽列」可使用早期的管控措施列上限56模式；48磅宽表通常应保留默认选项。新增行和安全余量可能增加打印页数，不为凑页数裁掉正文。打印时选择支持A3的打印机或PDF打印机。

## 原件保护与处理顺序

| 顺序 | 行为 |
|---|---|
| 1 | 只读原件，备份一次，建立工作副本 |
| 2 | 保持一行一条预处理，先不插行 |
| 3 | 先逐列估算宽度：中文/全角2.2、ASCII 1.0、余量2.4、下限8；普通自动宽上限48，已足够宽的不缩窄 |
| 4 | 再逐行计算高度：所有单元格需求取最大，横向合并使用列宽总和；纵向合并跳过非首格，利用已有各行高度，仅将不足部分补到首行 |
| 5 | 高度仍超过409.5磅才整行插入；先插行，再复制样式/边框/填充，最后重建纵向合并并扩展原横向合并块 |
| 6 | 处理后源表使用原文件名，明细仅保留周次；统一放进「（处理后）」文件夹 |
| 7 | 成功或失败都清理本次work副本 |

高度按「行数 × 字号 × 1.5 + 6」估算，文字宽度结合字号换算；空行15磅，有内容至少18磅，管控措施另加指定增量。自动换行、垂直居中、显式行高。原表存在远端成万空合并时，只清理工作副本中数据列以外的空白格式，避免虚假大范围拖垮导出。

预处理删除A列为「例/示例」、带删除线的示例行，以及「填报人/填报人及联系方式」行；统一换行并压缩连续空行，人员列姓名与电话跨行时直接拼接。

**标黄不等于示例：三级/3级风险保留；已识别的其他级别（如四级、五级）标黄行删除；无法判断级别时保留并警告。** 删除行涉及已有纵向合并首格时，将原值和原样式迁移到剩余合并区域首格并记录位置。

浏览器受文件权限限制，不会在硬盘创建工作文件夹：首次备份保存在当前浏览器的 IndexedDB，同名备份不覆盖；work是独立内存副本，用后清理。「源文件备份 ZIP」内包含 `源文件备份/原文件名.xlsx`，内容与首次原件逐字节一致。浏览器不允许持久存储时明确警告，改为本次会话备份，请及时下载ZIP。清理浏览器数据或更换浏览器/HTML位置可能使旧备份不可见，因此建议保存ZIP。

## 错误报告

报告包含文件名、原始单元格位置、错误代码和说明：日期与标题/文件名不一致、标题与文件名周次不一致、日期非法、时间缺日期、时刻无法解析、起止顺序异常、必需列/管控措施列缺失、异常合并、输出失败等。不按业务周次擅自推算ISO日期，不猜跨夜日期，不补造时刻。

有数据错误时仍可下载源表排版结果和报告，但暂停生成明细，修正原件后重新导入。异常合并或损坏工作簿会停止源表导出。含公式、表格或条件格式的源表会提示核对引用；不承诺自动改写复杂公式或保留ExcelJS不支持的Excel扩展功能。

## Python参考/批处理版

仅使用HTML无需本节。Python源表处理使用openpyxl；`source_processor.py`是源表入口，`weekly-plan-export.py`保留明细/汇总菜单。

```sh
pip install -r requirements.txt
python source_processor.py "表1（第37周）.xlsx"
python source_processor.py --directory "源表目录" --measures-plus 2
python source_processor.py "表1.xlsx" --strict-widths
python weekly-plan-export.py
```

Python在原文件旁独占创建一次 `源文件备份/原名.xlsx`（存在即跳过），复制到 `work/source-随机名/`，绝不保存回原件；只删除本次工作副本。源表、明细及源表报告写入原件旁的「（处理后）」目录。扫描排除 `~$`、明细、旧格式处理后源表、（处理后）目录、work、源文件备份，防止同名结果再次作为原件处理。输出路径若与输入相同会停止，保护原件。
